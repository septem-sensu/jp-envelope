Class: Loader

Loader

This class is the dynamic half of the frontend bootstrap: the header loads only the base scripts statically (utils, loader, registry, fieldValidator, BaseObject) — every view class, Chart.js and every stylesheet is requested by the Loader on demand (one class per file, file name = first letter lower case CamelCase). registerObjects() builds the complete bootstrap from the injected collector: per envelope one instance, then all resources awaited, then the registry entries, then app-ready — all-or-nothing; only without debug the rawObjects leave the namespace, a failed resource load keeps them (fail-loud).

new Loader()

This method is the constructor of the class: it carries the promise dedupe map for script and stylesheet loads (key: file name).

<async> createInstance(rawObject)

This method is phase 1 of the envelope pipeline: load the class file (promise dedupe), instantiate the class and copy the envelope data via fillObject(). It does not register yet — waiting for the resources and the registry entry belong to the caller (registerObjects) resp. instantiateRawObject.

loadClassFileAsync(rawObject)

This method ensures that the class file of an envelope exists in the window namespace: already loaded classes resolve immediately (constructor check on window), otherwise the Javascript file (firstLetterToLowerCase class name) loads on demand — the promise dedupe of loadScriptAsync prevents parallel double loads.

<async> loadNewObject(newClass)

This method loads a blueprint on demand (called by app.newObject): fetch on the JSON view viewNewObject, the envelope runs through the standard pipeline — the class file can load for the first time on this way. Errors (HTML answer at a wrong role, empty 500 body, network) tear the promise up, the catch sits in the app wrapper (overlay).

registerObjects()

This method builds the complete app bootstrap: it instantiates every envelope of the collector in parallel, awaits afterwards all loadResources() calls, registers the finished instances in the registry and fires app-ready only then. Without debug it deletes the rawObjects from the namespace afterwards — a failed resource load keeps them (fail-loud).
Returns:
Type
void
Example
loader.registerObjects();
