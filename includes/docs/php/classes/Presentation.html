Presentation extends BaseObject
in package
  • Application

presentation.php : 23

This class renders the output of the app: it assigns template variables and processes the templates (simple {{class::property}} replacement — objects and arrays are json encoded, unreplaced placeholders are removed from the output). In addition it provides static helpers around cookies, logging, mail delivery and formatting that the presentation and the auth share. Most methods guard CLI runs of the regression suites.

viewNewObject()

baseObject.php : 354

This method serves the json view behind index.php?view=viewNewObject&newClass=... and returns a blueprint instance in the collector envelope format for on-demand object creation in the frontend. Invalid newClass values arrive from the request layer already filtered as null — the response is then deliberately empty instead of an AppError, because json views do not carry an AppError channel.

writeCookie()

presentation.php : 117

This static method writes the auth cookie. Existing cookie values are merged, the cookie expires after 30 days. CLI runs of the regression suites return early: without HTTP headers setcookie would only be a warning — the login there continues via getUserFromId anyway.

initObject()

baseObject.php : 135

This method initializes the instance: class name, id, form fields and the persistence file path, followed by fillObject(). It exists as a separate method because createBlueprint() initializes instances past the constructor (subclass constructors resolve their own fallbacks, e.g. User falls back to the guest user) and needs the same source.
