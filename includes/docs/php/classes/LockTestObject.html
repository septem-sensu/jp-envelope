lockTest.php : 39

Local test object: a minimal BaseObject subclass that swaps the persistence file to the temp directory after construction (the constructor itself derives the never existing production path includes/json/data/locktestobjects.json, so fillObject stays a no-op) and inflates the serialization step to widen the read-modify-write conflict window of concurrent saves.

viewSaveObject()  : array<string|int, mixed>
This method serves the generic json save route behind index.php?view=viewSaveObject (POST): the request parameter 'object' carries the envelope { class, id, data } the client wants to persist — with the blueprint id the route creates (server generated id), without it the client addresses an existing object (merge update). The route accepts only CRUD-capable classes: a BaseObject subclass with a field definition — every other class name is silently filtered (like viewLoadObject, json views carry no information channel for foreign classes). The merged values follow the field contract: only declared fields arrive on the instance, NOSERIALIZE/NOSAVE properties and password fields are never merged, fields with a roleIds attribute only for roles the definition allows and the own id is immutable — at a create the delivered id is taken over the declared id field contract, the blueprint id itself is ignored (the server generates the id).
initObject()  : void
This method initializes the instance: class name, id, form fields and the persistence file path, followed by fillObject(). It exists as a separate method because createBlueprint() initializes instances past the constructor (subclass constructors resolve their own fallbacks, e.g. User falls back to the guest user) and needs the same source.

viewSaveObject()

baseObject.php : 597

This method serves the generic json save route behind index.php?view=viewSaveObject (POST): the request parameter 'object' carries the envelope { class, id, data } the client wants to persist — with the blueprint id the route creates (server generated id), without it the client addresses an existing object (merge update). The route accepts only CRUD-capable classes: a BaseObject subclass with a field definition — every other class name is silently filtered (like viewLoadObject, json views carry no information channel for foreign classes). The merged values follow the field contract: only declared fields arrive on the instance, NOSERIALIZE/NOSAVE properties and password fields are never merged, fields with a roleIds attribute only for roles the definition allows and the own id is immutable — at a create the delivered id is taken over the declared id field contract, the blueprint id itself is ignored (the server generates the id).

public viewSaveObject(Controller $objController) : array<string|int, mixed>

Reference properties (class/collection typed) arrive as the mirrored collector descriptors (propertyType, class, value) and are merged through mergeReferenceProperty(): the declared class comes from the property reflection, every delivered id is existence-checked, empty values clear the reference. Rejections travel as AppError envelopes (validation field errors and reference errors one envelope per field, the onSave hook and the guards one envelope per rejection); on success the response is the rawObject (envelope array) of the saved instance.
