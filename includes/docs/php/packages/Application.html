BaseCollection
This class is the abstract base class of the typed collections: an iterable container (IteratorAggregate, Countable) over instances of one allowed business class, declared per subclass through getAllowedType(). Every add access validates each element against that type and throws an InvalidArgumentException on a mismatch.

Diagnostics
This class represents the Diagnostics, which is a test run of all PHP test suites which contains the results of the individual system unit tests in the constant TESTSUITES.
FieldValidator
This class is the server side counterpart of the frontend fieldValidator.js: it validates request values against the form field definitions of a business class (includes/json/fields/{klasseKlein}.json) — the same single source of truth the frontend uses. Actions call validate() with the class name and an optional fieldset: without a fieldset every declared field is validated with its own mandatory flag (the create case), with a fieldset only the listed fields run — bare entries stay mandatory, boolean entries downgrade the field to optional. The method reports instead of aborting: it returns the first error message per field (field name => message), so actions can collect soft errors via addError() and keep their partial save semantics. Domain guards (existence, permissions, ownership) deliberately stay in the actions.
Presentation
This class renders the output of the app: it assigns template variables and processes the templates (simple {{class::property}} replacement — objects and arrays are json encoded, unreplaced placeholders are removed from the output). In addition it provides static helpers around cookies, logging, mail delivery and formatting that the presentation and the auth share. Most methods guard CLI runs of the regression suites.
Request
This class is the single access point for GET and POST parameters.
Role
This class represents a role with its view permissions (role.json).
User
This class represents a user account with its authentication and user management actions.
UserCollection
This class is the typed collection over User business objects: it declares User as the allowed element type of BaseCollection and inherits the container behavior from it.
View
This class represents a configured view (view.json): it binds a view method to a business class, carries the result type (empty = HTML, 'json' = JSON response), the template chain and the allowed role ids, and executes the actions and the view method of the view.
CollectionTestItem
Local test element: a minimal BaseObject subclass with one payload property and accessor. The base class provides id(), so the element is fully usable for the idArray() checks.
CollectionTestCollection
Local test collection: declares CollectionTestItem as the allowed element type.
PersistTestChild
Local test child: a minimal BaseObject subclass with one payload property — the allowed element type of the test collection and the target class of the 'class' reference of PersistTestObject.
PersistTestCollection
Local test collection: declares PersistTestChild as the allowed element type.
PersistTestObject
Local test parent: a BaseObject with one property of every property type of the persistence contract (builtin, class reference, collection) and a runtime property filtered by the own NOSAVE override. The nullable property declarations deliberately use the '?Class' form — getPropertyType()/getPropertyClass() read the bare type name via ReflectionNamedType.
TestObject
Local test object: a minimal BaseObject subclass with one serializable property for the collector checks.
PersistTestObject
Local test class: a minimal CRUD-capable BaseObject subclass with the declared field mixPayload (mandatory) and strSecret (NOSERIALIZE guard against forged envelope writes) plus the hook logic: a payload 'BLOCK' aborts the save route, a payload 'KEEP' reports on delete.
PersistTestElement
Local test class: the referenced element of the reference suite cases, a bare BaseObject subclass without own fields (persisted as the suite-owned id/class entry in persistTestElement.json).
PersistTestElementCollection
Local test collection: the typed container of the reference suite cases, allowed element type PersistTestElement.
PersistTestReferenceObject
Local test class: a CRUD-capable BaseObject subclass with the declared reference mix (one object reference and one collection reference, both onto PersistTestElement) beside the mandatory mixPayload field — the subject of the reference descriptor merge.
LockTestObject
Local test object: a minimal BaseObject subclass that swaps the persistence file to the temp directory after construction (the constructor itself derives the never existing production path includes/json/data/locktestobjects.json, so fillObject stays a no-op) and inflates the serialization step to widen the read-modify-write conflict window of concurrent saves.

Functions

getTemplateVar()  : mixed
This function reads a single template variable from the protected templateVars property of a presentation instance via reflection (e.g. the collector as 'default::rawObjects').
check()  : void
This function is the regression check helper of every suite: a passing condition prints the OK line, a failing condition prints the FEHLER line and stops the suite with exit code 1.
mockController()  : Controller
This function builds the mock controller of the suites: an anonymous Controller subclass whose constructor deliberately skips the parent constructor (the real one boots the whole app incl. auth). Without a view id only presentation, user and role exist; with a view id the view object is created and the request scope is set accordingly.
setParams()  : void
This helper resets the request state, sets the viewUserList scope (the action view of the user management) and applies the given parameters as POST values — the common prelude of every scenario.
crashView()  : View
This function builds the test view: an anonymous subclass that throws in a controlled way in the desired branch — without view id, permission check or real view call: only executeActions/executeView are replaced (reflection swap on the mock).
runWorker()  : void
This function is the child process entry: it runs one of the worker modes ('a'/'b' parallel race writers, 'h' lock holder as foreign process, 't' timeout writer), signals its readiness via a barrier file in the test directory and prints a short result token on stdout ('WORKER-OK', 'TIMEOUT-OK', 'KEIN-TIMEOUT'). Errors are reported as "WORKER-FEHLER: ..." with exit code 2, so the parent never hangs. The check() helper is never used here — OK/FEHLER lines belong to the parent only.
waitForFile()  : bool
This helper waits until a file exists or the timeout is reached.
waitGoFile()  : bool
This helper waits until the go signal file appears (worker-side call of waitForFile with a generous timeout).
